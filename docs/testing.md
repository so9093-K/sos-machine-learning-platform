# 테스트·검증·CI 기준

검증은 실제 결함을 발견하고 변경 결정을 돕기 위한 수단이다. 기능이나 계약이 중요하다는 이유만으로 테스트를 만들거나 유지하지 않는다. 테스트 수·커버리지·과거 CI 구성을 목표로 삼지 않는다.

## 검증을 선택하는 기준

- **무엇을 발견하는가?** 재현 가능한 구체적 실패와 검증 결과가 바꿀 판단을 설명할 수 있어야 한다.
- **왜 여기서 확인하는가?** 기존 검증·계약 경계·코드 리뷰 등으로 충분한지 먼저 살핀다. 중복 검증과 여러 계층의 동일한 계산 반복을 피한다.
- **비용이 정당한가?** 실행 시간뿐 아니라 환경 의존성, 오탐, 유지보수·실패 진단 비용을 탐지 가치와 비교한다. 중요도가 높아도 비용 대비 가치가 낮으면 자동화하지 않을 수 있다.
- **삭제해도 되는가?** 근거가 부족하거나 중복된 테스트는 삭제·통합한다. 대체 테스트나 정기 실행을 의무화하지 않는다. 제거한 레거시 기능의 전용 검증도 보존하지 않는다. 필요한 데이터 이전은 해당 마이그레이션의 책임이다.

새 검증이 실제로 필요할 때만 결함을 발견할 수 있는 가장 저렴한 계층을 택한다. UI에서만 나타나는 동작은 브라우저에서, 모델 계산·게시·저장 계약은 적절한 Python/인프라 경계에서 검토하되 계층별 테스트를 자동으로 요구하지 않는다.

## 실행과 CI

- 로컬의 빠른 검사는 `make check-fast`, 전체 검사는 `make check`다. 정확한 명령과 선행 조건은 [Makefile](../Makefile)이 정본이다.
- PR은 선택된 검사만, `main` push와 수동 실행은 전체 통합·브라우저 검사를 실행한다. 실행 조건과 작업 목록은 [CI 설정](../.github/workflows/ci.yml)이 정본이다. Python `pr` 표식과 Playwright `@pr`은 PR 실행 대상 선택용이며 보호 등록부가 아니다.
- 자동 선택 범위 밖의 변경에도 **추가 검증이 실제로 필요한지 먼저 판단**한다. 필요하면 관련 검사만 선택하고 결과를 PR에 남긴다. 불필요한 전수·야간 실행이나 별도 테스트 등록부·결과 재판정 계층은 만들지 않는다.
- pytest·Vitest·Playwright·Ruff의 종료 코드와 로그를 결과로 사용한다. 실행하지 않은 검사는 성공했다고 주장하지 않는다.

## 실패와 격리

실패·필수 검사 누락·검사 0건을 성공으로 처리하거나 무조건 재시도·Skip하지 않는다. 실패 원인은 제품·테스트·환경 문제로 구분한다. DB/S3 Fixture와 브라우저 Compose는 테스트 소유 자원만 사용하며 기존 사용자 데이터·Snapshot·Tag를 삭제하지 않는다. 상세한 격리·복구 동작은 [격리 실행기](../scripts/isolated_compose.py)를 기준으로 확인하고, 실패 로그·Trace에 비밀값을 노출하지 않는다.
