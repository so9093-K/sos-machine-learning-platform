# 검증 체계 상태

현재 브랜치는 기존 테스트 자동화와 검증 전용 실행기를 **초기화한 상태**다. 제품 계약이 자동으로 검증된다는 뜻이 아니다.

- 기존 검증 코드와 테스트 개수는 새로운 검증 체계의 설계 기준이 아니다.
- 제품 기능·API 타입 생성·실행 도구는 검증 체계와 별개의 책임으로 유지한다.
- 자동 검증이 없는 동안 변경 사항은 코드 리뷰와 실제로 수행한 수동 확인에 근거한다. 미확인 위험을 성공으로 표현하지 않는다.
- 다음 PR에서 제품 비전과 검증 아키텍처 이미지를 기준으로 공통 CLI·Native Runner·필요한 증거·Thin Adapter를 **새로** 구축한다.
- 검증 범위는 처음부터 완전할 필요가 없다. 실제로 가치가 확인된 계약부터 점진적으로 추가한다.
