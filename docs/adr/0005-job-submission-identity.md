# 0005 — 비동기 Job 제출 식별과 외부 커밋 안전성

- 상태: Accepted
- 범위: 공통 Job 제출·Actor 신원·데이터 변경 작업

## 배경

요청이 접수된 뒤 HTTP 성공 응답이 유실되면 재전송이 별도 Job을 만들 수 있다. Iceberg Append 중복은 Worker의 중단 후 자동 재시도 방지만으로 예방할 수 없다.

## 결정

1. `Idempotency-Key`를 보내면 Actor+제출 키를 PostgreSQL 유일성 제약으로 예약한다. 예약·Job 생성·감사는 단일 DB 트랜잭션이다.
2. 작업 종류·Dataset ID·정규화된 명세의 SHA-256 지문을 검사하여 동일 요청은 원래 Job을 반환하고, 같은 키에 다른 요청은 구조화된 409 오류를 반환한다.
3. 제출 기록은 Job과 함께 유지한다. 이미 실패·취소·성공한 Job도 기존 키로 새 실행하지 않는다. 실제 재실행은 새 키와 새 Job을 필요로 한다.
4. 기존 클라이언트와의 호환성을 위해 과도기에는 키 없는 구형 요청을 허용하지만, 해당 경로에는 중복 제출 방지 보장이 없다. 필수화는 API 이행 계약을 갖춘 별도 변경으로 완료한다.
5. Job 접수의 멱등성은 Iceberg 외부 Catalog 커밋의 exactly-once를 뜻하지 않는다. 불확실한 커밋은 보수적으로 수동 확인한다.

## 근거와 영향

서버 인스턴스의 메모리 잠금이나 버튼 비활성화에 의존하지 않는다. 중복 제출·권한별 키 범위·감사 실패 롤백은 PostgreSQL 통합 테스트로 검증한다.
