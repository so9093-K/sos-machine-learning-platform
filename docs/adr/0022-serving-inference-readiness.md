# 0022 — 배포 관측과 실제 추론 준비의 분리

- 상태: **Accepted**
- 대체: [ADR 0020](0020-serving-operator-visibility.md) 결정 3의 API 준비 판정, 결정 6의 온라인 서빙 연결 판정

## 배경

Dashboard의 배포 상태를 모든 추론의 선행 조건으로 사용하면 관리 경로의 일시 장애가
정상 복제본의 추론까지 차단한다. 배포 설정의 관측과 실제 응답의 검증은 다른 책임이다.

## 결정

- 추론 요청은 Dashboard를 조회하지 않는다. 실제 응답의 모델 판본·시작 설정 지문·출력 계약을
  의도와 대조한 뒤에만 전달한다. Endpoint 준비 상태도 실제 복제본의 판본·지문 응답으로 판정한다.
- Dashboard 조회 실패는 운영 상태 미확인으로 표시한다. 배포 Config 불일치는 계속
  `OUT_OF_SYNC`로 표시하지만, 올바른 복제본의 추론 가능 여부와 구별한다.
- 컨트롤러의 전체 Config 대조·복구, 새 판본 승격, 배포 시 자원 수용은 유지한다.
  Dashboard 장애 중에는 새 배포·자원 수용을 확인할 수 없다.
- API 기능 준비 상태의 온라인 서빙 연결은 실제 Serve HTTP Proxy의 생존 경로로 확인한다.
  특정 Endpoint의 준비 여부와 전체 Proxy의 연결 여부는 구별한다.

## 한계

시작 설정 지문은 응답한 복제본이 어떤 판본·설정으로 시작됐는지 확인하는 근거다.
현재 CPU 예약·복제본 수 등 외부에서 바뀐 운영 설정 전체를 증명하지 않는다.
이러한 드리프트의 탐지·복구는 Dashboard와 컨트롤러가 담당한다.
캐시나 별도의 준비 상태 저장소는 추가하지 않는다.
