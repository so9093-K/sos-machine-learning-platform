# 0009 — 검증 실행의 CI 독립성과 테스트 자산 수명주기

상태: **Accepted**

## 배경

SOS의 검증은 pytest·Vitest·Playwright 및 `make check-fast`·`make check`를 사용한다. 검증 절차가 특정 CI YAML에 결합되면 다른 실행 환경에서 같은 계약을 재현하거나 실패 근거를 비교하기 어렵다. 테스트 수가 증가하더라도 관리 정책은 최소한으로 유지해야 한다.

## 결정

1. **책임 분리:** Native Runner가 테스트 정의·실행의 정본이며, 저장소 공통 CLI는 Suite 선택·실행 결과·필수 증거와 실패 판정만 담당한다. CI 어댑터는 환경 준비·트리거·아티팩트 전달을 담당한다.
2. **재사용 경계:** 일반적인 테스트 수집·JUnit ID 정규화·대조는 공통 메커니즘으로 유지한다. 프로젝트별 Runner 수집 명령·테스트 경로는 설정으로 분리하고, Dataset·Job·Iceberg 등의 검증 계약과 환경 구성은 SOS가 소유한다. 별도 테스트 프레임워크는 재구현하지 않는다.
3. **실행 증거:** JUnit, 실행 식별자·코드 판본·Suite·시간이 포함된 Manifest와 Summary를 기록한다. 리포트 누락·손상·필수 Skip·미실행은 성공으로 판정하지 않는다. `make check-fast`의 무인프라 의미, `make check`의 전체 검증 의미와 `python-quality` 보호 게이트를 보존한다.
4. **수명주기:** 모든 테스트는 기본 `standard`이며 명시된 불변조건만 `protected` 계약에 연결한다. 계약 ID·선정 이유·연결 선택자 외에 등급·전수 메타데이터를 요구하지 않는다. Protected는 구체적인 테스트에 연결하고, 변경 자체에 별도 승인 절차를 추가하지 않는다. 검증 경로를 제거·대체할 때는 기존 실패 조건이 보호되는지 코드 리뷰로 확인한다.
5. **자원 안전:** 검증용 DB·S3·Compose의 생성·정리는 고유 소유권 경계를 따른다. 기존 개발·사용자 데이터와 Iceberg Snapshot/Tag는 자동 정리 대상이 아니다.

## 근거

테스트 실행·증거 판정의 반복 구현을 줄이면서 CI 제공자 또는 SOS 도메인 계약을 범용 로직에 고정하지 않는다. 공통 기능은 필요한 수준에서만 재사용하고, 실제 제품 의미는 계약과 Native 테스트에서 보존한다.

## 영향과 한계

GitHub Actions에서 공통 검증 경계를 호출하고 실제 결과를 대조한다. 다른 CI 제공자에 대한 지원은 요구가 있을 때 별도 어댑터와 실행 증거로 입증해야 하며, 추상화 자체가 외부 제공자 지원을 보장하지 않는다. 실행기 중단·소유권 확인 같은 자원 안전성은 독립 테스트와 리뷰로 검증한다. 세부 운영 정책의 정본은 [Testing & CI](../testing.md)이다.
