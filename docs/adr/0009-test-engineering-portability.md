# 0009 — 검증 실행의 CI 독립성과 테스트 자산 수명주기

상태: **Proposed**

## 배경

SOS는 pytest·Vitest·Playwright와 `make check-fast`·`make check`를 사용하며, GitHub Actions가 필수 검증의 실행과 결과 수집을 담당한다. 그러나 일부 검증 절차(예: PR 기준 OpenAPI 비교, Make 재시작·데이터 보존, 토큰 역할별 브라우저 검사)가 CI YAML 안에 구현되어 있어 다른 CI 제공자나 로컬 실행 환경에서 동일한 검증을 재사용하기 어렵다.

현재 `docs/testing.md`에는 주요 불변조건과 담당 테스트가 있지만, 개별 테스트의 자동 수집·목적 파악·변경·통합·폐기를 위한 공통 관리 경계는 충분히 정의되지 않았다.

이 ADR은 이번 PR의 설계 검토를 위한 **제안**이다. 구현과 검증 후 결정 내용과 상태를 최종 검토한다.

## 제안 결정

1. **검증 계약의 소유권:** 테스트 목적, suite 선택, 필수 실행 범위, 실패 판정 기준, 테스트 관리 정책의 정본은 SOS 저장소가 소유한다. GitHub·GitLab의 설정은 이 계약을 새로 정의하지 않는다.
2. **공통 실행 경계:** 로컬과 CI가 같은 검증 단위를 호출할 수 있는 CLI 경계를 둔다. 기존 `make check-fast`의 인프라 독립성, `make check`의 전체 검증 의미, PR `python-quality` 보호 게이트를 유지한다.
3. **Native Runner 유지:** pytest·Vitest·Playwright가 각각 테스트 수집과 검증을 담당한다. 공통 CLI는 전용 테스트 프레임워크를 재구현하지 않는다.
4. **결과와 실행 증거 분리:** JUnit XML, 실행 식별자·코드 판본·suite·환경 범위가 포함된 Run Manifest, Summary, 로그/Trace를 교환 가능한 산출물로 정의한다. 실패·누락·미실행을 성공으로 해석하지 않으며 비밀값을 기록하지 않는다.
5. **CI 어댑터의 제한:** 제공자별 워크플로는 트리거, 실행 환경 준비, 공통 CLI 호출, 아티팩트 수집, 품질 게이트 연결을 책임진다. OpenAPI 비교·RBAC·서비스 재시작과 보존 검사 같은 검증 로직은 CI YAML에 복제하지 않는다.
6. **환경 안전 경계:** 테스트용 DB·S3·Compose 프로젝트는 고유 식별자와 소유권에 따라 생성·정리한다. 기존 개발·운영 데이터, Iceberg Snapshot/Tag와 타인 소유 볼륨을 테스트 정리 대상으로 삼지 않는다.
7. **테스트 자산 수명주기:** Native Runner에서 실제 테스트 ID를 자동 수집하고, 보호 계약·영역·위험도·중복 여부 및 폐기 근거를 관리한다. 자동 탐지나 커버리지 수치만으로 테스트 또는 제품 코드를 삭제하지 않는다.
8. **이식성의 입증:** CI YAML을 작성한 것만으로 GitLab 호환성을 선언하지 않는다. 동일 CLI 및 실패·결과 계약을 독립 실행 환경에서 실제로 확인하고 미검증 범위를 명시한다.

## 근거

이 경계는 테스트의 의미와 실패 판정을 도구·플랫폼에서 분리해 실행의 이식성과 유지보수성을 확보한다. 별도의 상시 테스트 관리 서비스를 도입하지 않고 기존 Runner·Make·격리 실행기를 활용해 불필요한 중복 추상화를 피한다.

## 영향과 검증 조건

- 먼저 현재 `main`에서 관측된 HTTP 201 등록 후 목록 실패 E2E 문제를 실제 제품 결함과 테스트 경합으로 분류해 기준선을 복구한다. 실패를 Retry·Skip으로 숨기지 않는다.
- 공개 Make 명령, OpenAPI 호환성, Python·Frontend·E2E 필수 검증, DB/S3/Iceberg 데이터 보존과 역할 권한을 유지한다.
- 기존 필수 검사에서 누락 또는 불완전한 리포트가 발생하는 경우에도 성공으로 처리하지 않는 회귀 검증을 추가한다.
- GitHub 외 제공자 실행은 지원 범위와 실제 확인 여부를 분리하여 보고한다.
- 아키텍처 이미지는 사용자가 PR에 별도로 추가하며, 이 ADR은 이미지 파일이나 임시 이미지 참조를 만들지 않는다.
