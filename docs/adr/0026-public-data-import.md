# 0026 — 검증한 공개 데이터 가져오기

- 상태: **Accepted**
- 관련: [Contracts](../contracts.md#분석-주제), [Experience](../experience.md#데이터-탐색), [Runtimes](../runtimes.md), [Diagnostics](../diagnostics.md), [ADR 0021](0021-analysis-topic-contract.md)

## 배경

분석 주제의 가치를 확인하려면 정답 레이블이 있는 기준 데이터가 필요하다. 사용자 데이터에는 대개 레이블이
없으므로, 공개 데이터로 "어떤 검토량에서 무엇을 얼마나 잡는지"를 먼저 보아야 자기 데이터의 판정 기준을 정할
수 있다. 그러나 공개 데이터를 사용자가 직접 받아 형식을 맞추는 일은 첫 사용의 장벽이고, 임의 URL을 SOS가
받아 오게 하면 출처·이용 조건·무결성을 보장할 수 없다. 과거 합성 예제 경로(#130~#134)는 실제 데이터가 아니라
제거했다.

## 결정

1. **검증한 원본만 가져온다:** 가져올 수 있는 원본은 코드의 카탈로그(`public_datasets.py`)에 고정 URL·크기·
   SHA-256·이용 조건 판본·인용·준비 방법 판본과 함께 올린 것뿐이다. 임의 URL은 받지 않는다. 원본 추가·변경은
   코드 변경으로 검토한다.
2. **이용 조건 확인 후 명시적 Job으로 실행한다:** 요청은 사용자가 확인한 이용 조건 판본을 담아야 하며 현재
   판본과 다르면 거부한다. 가져오기는 공통 수명주기를 따르는 `public_import` Job이고, 접수 뒤 카탈로그가
   바뀌었으면 실행하지 않는다.
3. **결과는 일반 Dataset이다:** 원본의 한 부분이 Job 하나와 Dataset 하나다. Dataset은 요청자 소유이며 출처
   (원본·해시·이용 조건·준비 방법 판본·인용)는 만든 Job(`source_job_id`)의 명세와 결과에 남는다. 별도의 예제
   상태나 화면 전용 데이터가 아니다.
4. **원본은 해시로만 신뢰한다:** Worker는 원본을 받아 크기·SHA-256이 카탈로그와 같을 때만 쓰고, 다르면
   `SOS-PUBLIC-DATA-MISMATCH`로 실패한다. 받은 원본은 Worker 캐시에 해시 이름으로 둔 다시 받을 수 있는
   사본이다. SOS는 원본을 저장소·이미지에 포함하거나 재배포하지 않는다.
5. **준비는 생산 경로와 같은 함수로 한다:** 주제 입력 형식으로 바꾸는 준비(레이블·시각·무한값·제외 규칙)는
   Dagster 입력을 만드는 스크립트와 같은 함수를 쓰며, 입력 크기와 관계없이 스트리밍으로 처리한다.

## 근거

출처·무결성·이용 조건을 확인할 수 없는 데이터는 평가 근거가 되지 못한다. 카탈로그와 고정 해시로 범위를
제한하면 Worker의 외부 연결을 알려진 원본으로 한정하고, 같은 판본에서 같은 Dataset을 재현할 수 있다.
결과를 일반 Dataset으로 두면 탐색·준비·Scoring·평가를 별도 경로 없이 그대로 쓴다.

## 영향

- Worker는 카탈로그 원본 위치로 나가는 HTTPS 연결이 필요하다. 연결이 없으면 가져오기만
  `SOS-PUBLIC-DATA-UNAVAILABLE`로 실패하고 다른 기능에는 영향이 없다.
- `GET /api/public-datasets`, `POST /api/public-datasets/{source_id}/imports`가 추가된다.
- 첫 원본은 CIC-IDS2017 정정판(CNS2022)이며 네트워크 흐름 이상 탐지 주제의 학습·평가 부분을 만든다.
