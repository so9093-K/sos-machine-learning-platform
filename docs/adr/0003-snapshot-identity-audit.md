# 0003 — Snapshot 보존과 인증·권한·감사 경계

- 상태: Accepted
- 관련 결정: [0002 객체 보존](0002-object-lifecycle.md) (대체 관계가 아님)
- 범위: Data Workspace의 현재 로컬 실행과 외부 API 준비

## 배경

Snapshot ID 기록은 오래된 Iceberg Snapshot을 Catalog 만료 정책으로부터 보호하지 못한다. 초기 Data Workspace에는 인증된 사용자와 운영자를 구분하는 API 계약도 없었다. 정책과 구현 기술이 바뀌더라도 Dataset·Job·실행 결과의 의미를 유지해야 한다.

## 결정

1. Iceberg Dataset에 연결된 Snapshot은 Dataset별 고유 Tag로 Catalog에 먼저 보호한다. Tag에는 유효 수명 제한을 설정하지 않는다. Tag 생성과 PostgreSQL 게시가 서로 다른 트랜잭션이므로 영속적인 보존 의도, 실패 시 미확정 상태, 수동 재확인 경로를 제공한다. Tag의 자동 해제는 제공하지 않는다.
2. 작업의 Snapshot은 테이블의 단순 최신 상태가 아니라 실행 Attempt의 Snapshot 속성으로 식별한다. 동시 작성으로 유일한 Snapshot을 확인할 수 없으면 성공 게시하지 않는다.
3. **읽기 가능**과 **보존 확인**을 구별한다. 보존 참조가 없는 기존 Dataset은 사용 가능한 동안 `available_unprotected`, 보존 Tag까지 재확인되면 `retained`이다. 외부 객체 삭제 또는 권한 없는 Catalog 만료까지 Tag가 방지한다고 보장하지 않는다.
4. API 신원은 `Actor`로 정규화하고 행위·자원 단위로 권한을 평가한다. 초기 역할은 viewer, researcher, operator, administrator 프리셋이며, 미인가 접근은 기본 거부한다.
5. 개발 기본값은 명시적인 로컬 개발 신원이다. 프록시 전달 헤더를 감지한 개발 요청도 거부하지만 프록시가 해당 헤더를 제거하는 구성은 식별할 수 없으므로 외부 프록시 노출 금지가 필수다. 인증 필수 모드는 고엔트로피 불투명 Bearer 토큰의 **SHA-256 지문만 서버 환경에 저장**한다. 서비스는 TLS를 전제로 하며 외부 공개 기본 구성이나 OIDC 로그인은 아직 제공하지 않는다. 향후 OIDC 검증 제공자는 Actor 경계를 유지하며 추가한다.
6. 기존 `owner_actor=NULL`인 Dataset·Job은 레거시이며 기본적으로 관리자만 조회할 수 있다. 최초 로그인한 사용자에게 무단 이전하지 않는다.
7. 핵심 PostgreSQL 변경의 보안 감사 이벤트는 동일 트랜잭션에 기록한다. 거부 요청도 감사를 시도하지만 실패 시 별도 내구성 보장을 제공하지 않는다. Catalog 커밋과 감사 DB 쓰기는 하나의 원자적 작업이 아니므로 이를 운영 감사 WORM으로 주장하지 않는다.
8. 자동 객체 삭제, Tag 제거, 일반 사용자의 보호 완화, 인증 해제된 공개 모드는 제공하지 않는다.

## 영향·검증

- 신규 DB 스키마에는 Dataset·Job Actor 소유권, Snapshot 보존 의도, 감사 이벤트가 추가된다. 기존 데이터는 보존하되 자동 소유권 이전은 하지 않는다.
- 로컬 개발 UX와 데이터 처리 API는 기존과 같은 기본값으로 유지하되, 토큰 모드에서는 인증 필수·리소스 제한·역할별 UI를 적용한다.
- Snapshot 만료·동시 기록·Tag 생성 실패·DB 게시 오류, 401·403·404 리소스 격리, 감사 기록 실패의 복구 테스트를 운영 기능 도입 전 완료 기준으로 삼는다.
- OIDC, 프로젝트별 역할, 실제 배포 프록시·TLS, 변경 불가능한 외부 감사 저장소는 이 초기 구현의 기능이라고 주장하지 않는다.
