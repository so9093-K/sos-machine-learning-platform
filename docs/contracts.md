# 계약

플랫폼의 공통 개념과 컴포넌트 사이의 의미를 정의한다. **정확한 필드명·타입·기본값은 구현된 코드, 스키마 및 자동 생성된 API 명세**가 원본이며 여기서 복제하지 않는다. 계약은 특정 프레임워크나 서비스 제품의 내부 객체에 종속되지 않는다.

## 핵심 개념

| 개념 | 의미와 경계 |
| --- | --- |
| **Project** | 데이터·연구·모델·권한을 묶는 작업 범위 |
| **Experiment** | 연구 목적에 따라 관련 설정·실행·평가를 비교하는 논리적 묶음 |
| **Workflow Definition** | 재사용 가능한 작업 단계, 입력·출력·의존관계의 정의 |
| **Workflow Run** | 특정 Workflow Definition을 실행한 개별 기록. 하나 이상의 Job을 포함할 수 있다 |
| **Job** | 플랫폼에 제출된 단일 실행 요청과 그 수명주기를 추적하는 논리적 단위 |
| **Execution Attempt** | Job을 수행한 실제 시도. 재시도는 이전 시도와 구분된다 |
| **Dataset Reference** | 사용된 데이터의 소스·버전 또는 재식별 가능한 범위와 스키마 |
| **Model Revision** | 식별 가능한 한 모델 결과의 불변 판본. 가변적인 배포 별칭과 구분한다 |
| **Artifact** | 모델·전처리·평가·로그 등 생성·참조되는 결과물과 무결성 정보 |
| **Evaluation** | 특정 모델·데이터·지표·평가 조건의 조합으로 얻은 결과 |
| **Runtime Specification** | 작업을 실행하는 데 필요한 환경 및 호환성 요구 |

단순한 Job은 반드시 Workflow Definition에 속할 필요가 없다. 실험은 실행 자체가 아니며, Job과 실행 시도도 동일하지 않다. 모델 판본·아티팩트·배포 대상은 서로 다른 생명주기를 가진다.

## 모든 경계에서 지킬 규칙

- **식별과 연결:** 요청, 실행 시도, 입력 데이터, 모델 판본, 평가, 아티팩트와 Runtime을 안정적 식별자·참조로 연결한다.
- **결과의 보존:** 이미 생성된 모델 판본·평가 결과·아티팩트의 의미를 조용히 덮어쓰지 않는다. 재실행과 재평가는 새로운 기록으로 남긴다.
- **입출력 명시:** 데이터·모델 계약에서 형태(Shape), dtype, 컬럼, 시간 기준·타임존, 결측 및 값의 단위를 필요한 범위에서 표현하고 검증한다.
- **작업 의미:** 접수, 상태, 취소, 재시도, 오류의 의미는 [Workflows](workflows.md)와 일치해야 한다. 외부 API에서 중복 제출의 위험이 있는 작업은 멱등성 정책과 그 범위를 명확히 한다.
- **오류와 접근:** 기계 판독 가능한 오류 종류와 사용자 친화적 설명을 구분한다. 외부 시스템·에이전트도 동일한 권한·검증 규칙을 따른다.
- **호환성:** 후방 호환 가능한 확장과 호환성을 깨는 변경을 구분한다. 호환되지 않는 변경은 명시적 계약 식별 또는 마이그레이션 경로 없이 조용히 적용하지 않는다. 단, 사용자가 없고 외부 호출자가 존재하지 않는 사전 출시 단계에서는 명시적으로 승인한 구형 계약을 제거하고 코드·UI·테스트를 일괄 전환할 수 있다. CI는 승인 범위 밖의 계약 파괴를 계속 차단한다. 이 정책은 프로젝트 버전 `0.0.1`과 별개다.
- **Runtime 독립성:** 프레임워크가 다르다는 이유만으로 공통 플랫폼 계약의 의미가 바뀌지 않는다. 다만 모델 파일이 모든 Runtime에서 읽힌다고 약속하지 않으며 호환성을 명시적으로 검증한다.

이 문서는 계약의 **의미와 지속 조건**을 정의한다. 세부 API 엔드포인트·필드 목록, 플러그인 SDK와 직렬화 형식은 실제 구현·검증과 함께 정의한다.

## UI 권한·표시 설정 계약

- 사용자 화면의 기능 가시성은 인증 API에서 서버 역할 정책으로 계산한 `capabilities`를 사용한다. UI 제어는 편의 기능이며 서버의 Action 검사가 최종 권한 정본이다.
- 인스턴스 표시명은 영속화된 표시 설정으로만 취급하며 인증 모드나 배포 환경 의미를 갖지 않는다. 인증 모드는 `/api/v2/auth/me`를 정본으로 사용한다.
- EDA 차트 색상은 의미론적 CSS 토큰을 유일한 기준으로 사용한다.

## 탐색 후보와 분석 실행 계약

- Dataset Understanding의 후보는 업무 목적에 대한 권고가 아니라 입력 데이터 특성으로 구성한 **실행 가능한 탐색 조건**이다. 후보의 생성 근거·원본 Dataset 판본·프로파일 범위와 실제 Exploration의 계산 범위를 분리한다.
- 후보를 선택해도 계산하지 않는다. 선택된 `ExplorationSpec`는 탐색 화면에서 편집할 수 있고, 직접 작성한 조건과 동일한 API로 실행한다. 전체 분석은 기존 Job 계약을 통해 별도로 제출한다.
- 웹 초안은 Dataset ID와 버전에 귀속시키며, Dataset 전환 시 기존 후보·조건·결과를 폐기한다. 기존 API의 `insights` 필드명은 호환성을 위해 유지한다.

## 구분 텍스트 Dataset 해석 계약

파일 Dataset은 제한된 포맷 Reader 등록 지점에서 입력 옵션·유효성·DuckDB/Polars 읽기 책임을 분리한다. 확장자는 지원 Reader를 선택하는 단서이며 원본 바이트 해시와 Dataset별 해석 옵션을 대체하지 않는다. 기존 CSV·Parquet 등록 의미를 유지하며 탭 구분 TSV/TXT에는 등록 시 확정한 헤더 유무를 Dataset에 귀속시킨다. 헤더가 없는 컬럼은 순서대로 `unnamed_1`부터 식별한다. 원본 바이트의 SHA-256은 무결성·캐시 기준이고 Dataset의 해석은 Dataset ID·원본 판본·입력 해석 설정을 함께 고려해야 한다. 같은 원본 바이트라도 다른 헤더 설정이면 서로 다른 Dataset 참조로 등록한다. Preview·Profile·Worker·Feature 연산은 같은 설정을 사용한다. 탭이 없는 일반 TXT, 일관되지 않은 열 수, 잘못된 UTF-8과 헤더는 임의로 추측·복구하지 않고 거부한다.

TSV/TXT Multipart 업로드 파일 파트의 MIME은 `text/tab-separated-values; header=absent` 또는 `text/tab-separated-values; header=present`로 선언한다. 서버는 선언을 확인하여 Dataset 해석 설정으로 보존한다. CSV·Parquet 기존 API 계약은 변경하지 않는다. 이 지원 범위에서는 따옴표를 일반 문자로 해석하므로 탭·줄바꿈을 인용하는 다른 TSV 방언은 지원하지 않는다.

## Dataset Understanding 결과 계약

Dataset Understanding은 Dataset 자체가 아니라 특정 원본 판본과 프로파일 알고리즘·샘플링/전체 분석 범위에 대한 **불변 결과**다. Job/Attempt가 실행의 정본이며 성공한 Profile은 별도 참조로 확정된다. 동일 원본에 대한 재계산은 기존 결과를 덮어쓰지 않는다. 행 수·결측·고유값 계산의 범위와 정확도(정확/근사)는 독립적인 속성이다. 컬럼의 역할은 근거가 있는 후보이며 확인되지 않은 업무 의미나 Target으로 확정하지 않는다. 사용자에게 제안하는 분석은 현재 API가 검증·실행할 수 있는 정의여야 하고 변환은 사용자의 선택을 필요로 한다. 탐색 제안을 생성한 입력 범위와 제안을 실행하는 인터랙티브 표본의 범위가 다르면 사용자에게 구별해서 안내한다.

## 분석 결과의 범위·근거 계약

데이터를 **미리보기**로 조회하는 행 수 제한, **부분 데이터 분석**의 선택 방식, **전체 데이터 분석**의 입력 범위는 서로 다른 의미다. 분석 결과의 근거는 (1) 원본 Dataset과 판본, (2) 전체/부분 입력 범위와 데이터 선택 방식, (3) 요청 한도와 실제 분석한 행 수의 구별, (4) 개별 지표의 정확·근사 계산 방식, (5) 반환·표시된 결과의 제한으로 분리한다. 제한 조회는 명시적인 정렬 없이는 대표 표본이나 원본의 첫 N행으로 표현하지 않으며, 무작위 표본도 대표성을 보장하지 않는다. **전체 데이터 분석은 모든 통계값이 정확함을 뜻하지 않고**, 전체 그룹 집계와 일부 그룹 표시는 공존할 수 있다. 미계산·미확인 정보는 0이나 정확한 값으로 대체하지 않는다.

현재 Understanding은 원본 판본·선택 방식·Seed·알고리즘 판본·실제 분석 행 수를 제공한다. Discovery Profile은 제한 조회와 실제 분석 행 수를, Exploration은 분석 범위·조회 상한·그룹 표시 제한을 제공하되 실제 분석 행 수나 선택 알고리즘 판본은 응답에서 보장하지 않는다. **현재 응답에 없는 근거는 UI가 추정해 채우지 않는다.** 선택 알고리즘·표본 정책이 가변화될 때에는 이전 결과의 근거를 재해석하지 않도록 실행 시점의 방식·설정·알고리즘 판본을 결과에 결부시키고, 기존 필드의 의미를 변경하지 않는 호환 가능한 계약 확장을 우선한다. 결과 비교는 Dataset 판본·조건·선택 방식·계산 방법이 비교 가능할 때에만 성립한다.

## 현재 Data Workspace의 계약 적용

- **Dataset:** 파일은 내용 해시로, Iceberg는 유효한 Snapshot ID로 입력 버전을 식별한다. 합성 예제도 동일한 Dataset 참조와 등록 과정을 사용한다.
- **Discovery:** DuckDB로 기본 스키마·샘플 Preview·Profile·집계를 조회한다. 대화형 집계는 정렬 없는 제한 조회에 기반하며 전체 분석은 기존 Worker의 별도 Job으로 실행한다. 데이터 판본·샘플 범위·결과 그룹 제한은 분석 결과의 의미를 결정한다. Parquet Footer에서 확인된 행 수와 소스별 행 수 미계산 상태를 구별한다. Preview는 NaN·양/음의 무한대를 JSON 문자열 `NaN`·`Infinity`·`-Infinity`로 명시하고 실제 NULL과 구분한다. 임의 바이너리는 `base64:` 접두 문자열, DECIMAL과 IEEE-754 안전 정수 범위 밖의 정수는 정밀도를 보존하는 십진 문자열, 시간 값은 ISO-8601 문자열로 직렬화한다. 실제 컬럼 dtype이 해석 기준이다. 숫자 집계의 비유한 결과는 **그룹 정렬·제한 이전**에 JSON NULL로 정규화하며, 샘플과 전체 Job에서 동일하다. DECIMAL의 AVG는 DuckDB 실수 집계이므로 근사값이며, DECIMAL의 MIN/MAX와 큰 정수의 값은 정밀 문자열을 유지한다. 기존 Job 응답 계약은 확장하지 않고 Discovery Job을 별도 API로 제공한다.
- **Feature:** 단계 순서, 시간 정렬 및 선택적 그룹 기준은 변환 의미의 일부다. Lag는 이전 행을 참조하고 Rolling Mean은 현재 행을 포함한다. 그룹 간 값이 섞이지 않도록 검증한다. 동일 그룹의 중복 시간키와 NULL 시간키는 시계열 연산 이전에 거부한다. 선행 변환에서 시간 컬럼을 캐스트·필터링하면 적용 이후의 시간값으로 검증하고 정렬한다.
- **Feature Preview:** Row-local 변환은 Lazy 투영·필터·출력 제한으로 입력 전체 행수에 제한받지 않는다. 전역 정렬·윈도는 동기 예산을 검사하고 초과 시 전체 Transform Job으로 안내한다. 실제 변환이 아닌 잘린 입력의 결과를 전체와 같다고 표시하지 않는다. Dataset Query는 검증된 컬럼·비교·정렬만 허용하며 임의 SQL·경로를 받지 않는다.
- **비동기 실행:** 토큰 인증 환경에서는 비동기 Job 요청의 Idempotency-Key가 필수이며, Actor·요청 명세의 원자적 제출 신원을 보존한다. 개발 모드에서 Idempotency-Key 없이 제출한 요청에는 이 보장이 적용되지 않는다. Iceberg 적재는 중단 직전 커밋됐을 수 있어 불확실한 중단 후 무조건 재시도하지 않는다. Snapshot을 검사한 후 별도 실행으로 처리한다.
- **정확한 API 타입:** 구현된 Pydantic 입·출력 모델이 OpenAPI의 기준이며, 웹 타입은 이 명세에서 생성한다. 생성 타입을 별도로 수작업 정의하지 않는다.
- **Iceberg 적재:** 비파티션 테이블은 스트리밍 스테이징과 배치 읽기를 단일 Snapshot으로 커밋한다. 외부 커밋이 불확실한 상황에서는 자동 재적재하지 않는다. 기존 파티션 테이블은 Reader 쓰기 미지원으로 소규모 호환 경로를 유지한다. 로컬 임시 디스크와 실제 부하 예산은 환경별 검증 대상이다.
- **Job 목록:** 최신 생성 시각·식별자 역순으로 커서를 통해 페이지 단위로 조회한다. 목록은 최대 100개 요청을 허용하며 Attempt 전체가 아닌 총 시도 횟수·마지막 시도 요약만 포함한다. 개별 Job 조회는 전체 Attempt 이력을 유지한다.

## Iceberg 테이블 쓰기 권한

- 테이블에 대한 쓰기 권한은 `datasets.owner_actor`로 표현되는 Snapshot 읽기·연결 권한과 독립적이다. 신규 테이블명 예약은 Job 멱등성 확인과 동일 PostgreSQL 트랜잭션으로 확정하여, 실패한 중복 요청이 다른 이름을 선점하지 않도록 한다.
- 신규 테이블은 PostgreSQL의 고유 이름·소유 Actor·무작위 토큰을 먼저 예약하고 실제 Iceberg Catalog Table Properties의 동일 토큰과 물리 Table UUID를 고정·검증한다. 같은 이름·토큰으로 다시 생성된 다른 UUID의 테이블은 기존 소유권을 재사용하지 못한다. 다른 Actor의 이름 충돌은 거부한다.
- API 제출 및 Worker 외부 커밋 이전의 실제 Table 메타데이터를 모두 검증한다. 미확정·소유권 불명·토큰 불일치·소실된 기존 테이블에는 자동으로 쓰기를 허용하지 않는다. 레거시 Snapshot 참조와 Tag는 그대로 유지한다.
- 테이블 쓰기 소유권은 현재 한 Actor에게 귀속하며, administrator의 조회 권한을 자동 append 허가로 해석하지 않는다. 관리형 로컬 환경에서 한 명의 명시적 소유자로 확인되는 레거시 테이블만 Table UUID·Snapshot·기존 Dataset ID를 명시한 운영자 CLI로 채택할 수 있다. 임의 소유권 양도나 API를 통한 인수는 지원하지 않는다.

## Actor·보존 참조 계약

인증 제공자가 달라져도 검증된 Actor·Action·Resource에 대한 접근 판단 의미는 유지한다. 기존 데이터의 소유자가 기록되지 않았다고 해서 최초 접근자가 자동 소유자가 되지 않는다. Iceberg Dataset의 Snapshot ID는 읽을 판본을 식별하며, 실제 보존 상태는 Catalog에서 Tag 참조와 만료 정책을 재확인해야 한다. 보존되지 않은 과거 Snapshot은 사용 가능과 보존 보장을 혼동하지 않는다. 자세한 운영 결정은 [ADR 0003](adr/0003-snapshot-identity-audit.md)을 따른다.
