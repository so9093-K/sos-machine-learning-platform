# 사용자 경험

사용자 경험은 화면을 만드는 마지막 단계가 아니라, 기능의 경계·상태·API 계약을 결정하는 설계 입력이다. 기능은 사용자 목표와 성공 기준을 먼저 이해하고 UX, 계약, 구현, 검증을 반복해서 맞춘다. [제품 정체성](vision/PLATFORM_IDENTITY.md)의 Fork·Compare·Reproduce·Understand·Explore·Apply는 연구 경험의 기준이다. 이 문서는 사용자가 무엇을 할 수 있어야 하고 어떤 상태와 오류를 이해해야 하는지 정의하며, 메뉴 배치·화면 구성·문구는 구현이 정본이다.

## 이용자별 경험

![모델 개발·운영과 모델 활용의 두 경험](references/builder-consumer-experience.png)

**개발 환경에서는 기능을 만들고, SOS에서는 그 기능의 가치를 경험하게 한다.** Builder / Operator는 프로젝트 코드·MLflow·Dagster·Feast 등 개발·운영 환경에서 모델과 기능을 만들고 검증한 뒤 배포 과정으로 SOS에 공급한다. Consumer / Explorer는 준비된 모델의 목적·제약·입출력을 확인하고 자신의 데이터에 적용해 결과를 이해한다. 두 경험은 동일한 모델 판본과 평가 근거를 참조한다.

![연구 경험·모델 운영 경험·모델 사용 경험의 사용자 목표와 질문](references/research-operations-model-experiences.png)

| 이용자 | 핵심 경험 |
| --- | --- |
| **Human** | 데이터 탐색·모델 개발·평가·배포 운영 또는 모델 소개·Playground·API 연동을 목적과 권한에 맞게 활용한다. 기술적 세부 정보는 필요할 때 단계적으로 제공한다. |
| **External System** | 명확한 요청·응답, 비동기 작업 식별, 상태 조회, 구조화된 오류, 중복 요청 처리와 예측 가능한 호환성에 기반해 연동한다. |
| **AI Agent** | 사람이 쓰는 핵심 기능을 공통 API·도구 계약으로 발견하고 사용할 수 있어야 한다. 작업의 권한과 부작용, 상태, 결과를 기계적으로 판독할 수 있어야 한다. |

웹 UI는 공통 플랫폼 기능을 활용한다. 특정 화면만 사용할 수 있는 숨겨진 핵심 기능이나 UI에 종속된 실행 계약을 만들지 않는다. API-first가 웹 사용성의 대체물은 아니다.

## 모델 활용

1. **발견:** 사용 가능한 모델과 그 목적을 찾는다. 준비된 모델이 없으면 그 상태를 분명히 알고, 데이터 탐색은 그대로 사용한다.
2. **이해:** 모델이 무엇을 하는지, 어떤 입력에 쓸 수 있는지, 무엇을 신뢰해서는 안 되는지 제공 설명과 고정된 판본 근거로 확인한다.
3. **적용:** 허용된 범위에서 자신의 Dataset이나 직접 입력에 모델을 적용한다. 계산은 명시적 사용자 행동으로만 시작하고 실제 상태를 확인한다.
4. **결과 이해:** 점수 분포·관측값·설명·판정 정책·평가를 근거와 한계와 함께 확인한다. 측정 불가능한 진행률이나 정확도를 추측해 표시하지 않는다.
5. **활용:** 결과를 자신의 작업에 활용하고 같은 모델로 다른 데이터나 입력을 다시 살펴본다.

이 과정은 모든 사용에 강제되는 단일 화면이나 순서가 아니다. 모델 제작자를 찾거나 학습 Job을 제출하거나 Experiment를 고르는 일은 모델 활용의 전제가 아니며, 모델이 없을 때 사용자에게 학습을 대안으로 요구하지 않는다.

활동 이상 탐지는 제공 모델을 자신의 Dataset에 적용하는 흐름을 기본으로 둔다. Dataset 선택·등록 후 모델의 필수 Feature·자료형을 확인하고, 명시적으로 실행해 점수 분포·주요 관측값·설명을 조사한다. 개별 관측값은 값 직접 입력에서 계산한다.

모델 상세는 사용 목적·입력 조건·생성 근거·평가 근거를 연결한다. 학습 출처·저장 근거·매개변수·학습 규모·내부 선택·결측 정책·학습 점수 집계는 공급자·관리자 전용이며, 소비자에게는 조회 제한임을 표시한다. 모델 생성·Registry 등록·사용 가능 상태와 독립 평가 근거·업무 적합성은 구별하며, 연결된 평가가 없으면 생성 기록만으로 성능을 보장하지 않는다. 최신 평가의 기본 표시는 대표 성능이나 승인이 아니며 평가 부재·접근 제한·조회 실패를 구별한다. 공급자의 비공개 평가는 모델 제공으로 공개되지 않는다. 모델 선택 전에 소비자에게 공개할 검증 요약은 별도 제품 정책이 필요하며 현재 제공하지 않는다.

모델 적용은 하나의 공통 흐름으로 제공한다. 입력 구조(Feature 이름·순서·기록된 자료형)는 목록·적용 화면·API가 같은 규칙으로 비교하고, 불일치는 선택 Dataset의 적용 제한으로 원인 컬럼과 함께 알린다. 구조 일치는 업무 적합성이나 성능 검증을 뜻하지 않으며 값·결측·자원 제약은 실행에서 최종 검증한다. 제공·적용 권한은 [Contracts](contracts.md#권한과-표시-설정)를 따르고, 결과는 실행한 사용자의 기록으로 남는다. 실제 모델·실행 근거가 없을 때 예시 결과를 실제 기록처럼 만들지 않는다.

## 모델 공급

모델 알고리즘·학습 설정·실험·지표 추적은 개발 환경과 MLflow 등 연구 도구에서 수행한다. 준비한 모델은 배포 과정의 자동화 계정이 SOS Worker로 학습해 판본·Runtime·Registry 근거를 남기고, 목적·적용 대상 데이터·한계 설명과 함께 제공한다. 학습이나 Registry 등록이 다른 Actor 대상 제공을 자동으로 시작하지 않으며, 소유 자동화 계정 또는 관리자가 명시적으로 제공·설명 갱신·중단한다. 제공은 SOS에서 신규 적용을 허용하는 일이며 MLflow 승격·Serving 배포·성능 승인이 아니다. 제공 중단은 새 적용만 막고 이미 만든 결과를 유지한다.

모델 상세에서는 권한 있는 소유자·관리자가 대상 판본과 자원 사용을 확인하고 기존 API로 최초 Endpoint 배포를 명시적으로 요청한다. 복제본의 Runtime 준비와 API 호출의 Registry·권한·입력 검증을 구별하며, 명시적 배포 실패에서는 자동 조회 간격을 늦추고 수동 재조회를 제공한다. 안정·중단 상태도 느린 주기로 다시 확인하고 마지막 성공 확인 시각을 표시하며, 조회 실패가 그 시각을 갱신하지 않게 한다. 공급 자동화도 같은 API로 배포·새 판본 전환을 요청한다. 소유 계정은 **온라인 서빙** 화면에서 지금 요청을 처리하는 판본과 실제 실행 상태·실패 사유를 확인하고, 직전 판본으로 되돌리기·전환 취소·중단·재개·삭제를 실행한다. 새 판본은 준비가 확인된 뒤에만 전환되므로 전환 중이나 실패 시에도 기존 판본이 계속 요청을 처리한다.

## 분석 주제

사용자는 **학습 유형 → 분석 과제 → 주제 Playground → API 연동** 순서로 ML 기능의 가치를 발견하고 자신의 일에 쓰는 방법을 이해한다. 목적은 알고리즘 학습이 아니라 결과의 의미와 활용 방법을 이해하는 것이다. 학습 유형·분석 과제·주제는 독립적인 분류 축이며 탐색 화면의 계층은 이 속성에서 만든 표시 방식이다. 첫 제공 주제는 '비지도 학습 / 이상 탐지 / 활동 이상 탐지'다. 주제에서 적용하는 모델은 주제의 입력·출력 계약을 따르는 모델이며, 어떤 알고리즘이나 등록 Pipeline으로 만들었는지는 묻지 않는다([Contracts](contracts.md#분석-주제)).

- **학습 유형:** 개요와 도식으로 무엇을 가능하게 하는지, 어떤 상황에 쓸모가 있는지 보여주고 SOS가 지원하는 분석 과제로 연결한다.
- **분석 과제:** 원리 도식, 활용 방법, 결과 해석의 주의점을 보여주고 모델을 적용할 수 있는 주제로 연결한다.
- **주제별 모델 적용:** 자신의 Dataset을 선택·등록하는 화면을 먼저 보이고 제공 모델을 Dataset·직접 입력에 적용해 결과를 확인한 뒤 결과 해석과 같은 계산의 API 요청으로 이어진다. 선택 모델이 온라인 API로 서빙 중인지 표시하고, 값 직접 입력에서 계산한 입력을 온라인 추론 요청 예시로 채워 화면에서 바로 보내 같은 점수를 확인한다. Dataset 전체 점수는 비동기 Scoring Job 요청 방법으로 안내한다. Feature 계약·모델 판본 같은 기술 정보는 펼쳐 확인한다.

분류와 주제는 SOS가 실제로 지원하는 것만 연결하며, 개요 도식의 일반 개념을 제공 기능처럼 표시하지 않는다. 등록 Pipeline·모델 학습·Registry 같은 공급·운영 정보는 관리자 계정이어도 Playground의 흐름에 두지 않는다. 기본 모델 선택은 주제의 Feature 계약을 따르며 선택 Dataset에 대한 추천이 아니다.

## 결과 조사

- **결과 우선:** 관측 수·점수·분포를 판본 식별자보다 먼저 보여준다. 분포 요약은 보존된 히스토그램 구간의 실제 집계로만 만들고, 보존되지 않은 분포를 재구성하거나 판정 임계값·사건 수처럼 표현하지 않는다. 판정 정책 없는 점수 순위와 정책을 적용한 검토 대상을 구별한다. 자동으로 보여준 관측값은 사용자가 직접 선택한 관측값과 구별하며, 전체 결과 집계는 관측값 선택에 따라 바뀌지 않는다.
- **관측값 조사:** 입력 프로필에서 실제 입력과 학습 분포·중앙값을 비교하되 차이를 원인·기여도나 정상 판정으로 단정하지 않는다. 입력 단위가 다른 항목은 각각의 학습 범위와 비교하며, 학습 구간 밖 여부와 학습 기준 대비 차이로 일부 항목을 먼저 보여주고 전체 입력은 상세에서 확인한다. 입력 실험에서는 기본 항목의 순서를 유지하고 직접 수정한 항목을 별도로 드러낸다. 학습 분위 경계의 실제 값과 구간 밖 차이를 툴팁 없이 읽을 수 있게 표시한다. 참고 분포는 분석 비용을 제한한 결정적 표본으로 계산할 수 있으며, 권한이 있는 계정에는 전체 학습 행 수·표본 수를 표시하고 소비자에게도 근사 분포임을 명시한다. 표본의 최솟값·최댓값을 전체 학습 데이터의 경계로 표현하지 않는다. 분포 기록이 없는 판본은 중앙값만 비교하고 분포를 추정하지 않는다. 입력의 결측·유효성 문제는 계산 전에 알린다.
- **설명:** 점수 설명은 선택적으로 펼치는 Permutation SHAP으로 제공하며 비교 기준(단일 Train 중앙값 합성 배경 등)을 계산 전후에 함께 표시한다. 특정 입력을 학습 초기값으로 바꾸는 실험은 입력 편집과 명시적 재계산에 연결한다. 기존 Feature 치환 설명 결과는 결과 상세에서 계속 확인할 수 있다. 재구성 오차를 개별 기여도의 정확도로 해석하지 않는다. 결과가 모두 0이면 원래 기준값과 같은 입력이었는지, 값을 바꿔도 점수가 같았는지를 실제 계산 근거로 구별하고 다음 행동을 안내한다. 변화가 있는 항목을 먼저 비교하고 전체 수치는 검색해 확인한다.
- **단일 입력 실험:** 제공 모델의 입력을 직접 수정해 Dataset 등록 없이 소량 점수화하며, 학습 중앙값을 조합한 초깃값은 실제 관측이나 정상 활동 예제와 구별한다. 입력값과 결과는 Job으로 보존돼 다시 비교할 수 있다. Dataset 관측값을 초깃값으로 가져오는 것은 전체 필수 Feature·자료형이 유효할 때만 허용하고 자동 실행·자동 보정하지 않는다. 원래 결과는 유지하며, 같은 입력의 재계산은 저장 점수의 재확인임을 알린다. 원래 관측값 복원과 학습 기준값 초기화는 다른 행동이다. 제출 당시의 입력·결과는 이후 편집값과 섞지 않으며 반올림에 가려진 차이와 실제 일치를 구별한다.
- **식별과 한계:** 관측치 ID는 검증된 UUIDv4가 있을 때만 연결하며 형식만으로 비식별성을 보장하지 않는다. 집계 Feature 관측치와 원본 로그의 단일 이벤트를 구별한다. 레이블 없는 이상 탐지에서는 경보 비율과 점수 분포를 보여줄 수 있지만 탐지 정확도를 확정한 것처럼 표현하지 않는다. 같은 점수에 대한 정책 비교는 재학습을 요구하지 않는다.

모델 유형에 따라 입력·출력 경험은 다를 수 있으며 이상 점수·Feature 설명을 모든 모델의 공통 화면으로 강제하지 않는다. 조회 실패와 실제 Job 실패는 다른 상태이고 기술 오류의 ID는 진단 근거로 보존한다.

## 등록형 Pipeline 경험

Pipeline Creator는 개발 환경에서 Workflow Definition을 정의·검증해 배포한다. 학습 권한이 있는 운영 계정은 SOS에서 등록 Pipeline을 실행해 모델을 공급하고 단계별 결과를 조사한다. Pipeline Consumer는 Pipeline 자체가 아니라 그 결과로 제공된 모델과 근거를 모델 활용에서 경험하므로, 등록 Pipeline은 일반 사용자의 메뉴와 분석 주제 화면에 노출하지 않는다.

실행 결과에서는 입력·시간 분할, 학습 모델, Calibration 점수와 판정 기준, Test 점수와 평가의 관계를 확인한다. 주요 결과를 먼저 요약하고 관측값·결과 판본을 조사하며 기존 결과 화면으로 이동한 뒤 원래 실행으로 돌아올 수 있다. 결과 조회와 새 실행 권한은 구별해, 기존 실행의 직접 링크는 작업 조회 권한으로 열람하고 새 모델 학습을 포함하는 실행은 권한 있는 Actor가 자원 사용을 확인하고 명시적으로 제출한다. 구조 사전 검사와 Worker의 전체 입력 검증, 학습 완료와 Registry 등록 완료, 조회 실패와 실제 단계 실패를 구별한다.

Dagster는 Workflow 정의·상태, MLflow는 실험 기록·Registry의 정본이다. SOS는 이 상태를 복제하지 않고 단계별 Job과 확정 결과를 연결하며, 외부 운영 도구에 SOS Actor별 접근 계약이 적용된다고 가정하지 않는다. Dagster 재실행과 SOS의 새 제출을 구별하고, 단계 Job의 실패가 확인되지 않으면 실패 지점을 추정하지 않는다. 등록 Pipeline 실행은 모델의 다른 Actor 대상 제공을 뜻하지 않는다. 실행 상세는 고정 입력 판본의 규모·준비 Job·원본 Dataset(Feast는 Feature Source와 Entity 시점 Dataset 둘 다), 시간 분할과 실제 학습 선택, 모델 게시·Registry·제공·온라인 배포 상태를 연결한다. 참고 분포의 분석 행 수와 모델 학습 행 수, 저장 기록과 현재 객체 무결성 재검증을 구별한다. 출처가 없거나 조회할 수 없으면 다른 입력 경로로 추정하지 않는다. 모델 상세의 제공·배포와 운영 상태로 이동한 뒤 원래 실행으로 복귀할 수 있다.

## Feature 정의

Feast Feature 정의의 등록·조회·폐기는 배포 자동화가 SOS API로 실행하며 웹 관리 화면은 제공하지 않는다. 공식 Feast UI는 SOS Actor별 접근을 보장하지 않으므로 사용자의 작업 진입점으로 노출하지 않는다. 의미는 [Contracts](contracts.md#등록-feature)를 따른다.

## 데이터 탐색

- **처음 보는 Dataset:** 등록하면 원본의 규모·스키마·판본을 먼저 확인한다. 시스템은 데이터 사전 없이 통계·품질·역할 후보를 제시하지만 불확실한 판단을 확정된 업무 의미로 표현하지 않으며 원시 민감값을 자동 인사이트로 노출하지 않는다. 탐색 후보는 근거와 프로파일 범위를 함께 설명하고 사용자 확인·수정을 거쳐 실행한다. 데이터 이해만으로 작업을 끝낼 수 있다.
- **구분 텍스트:** 헤더 유무와 해석 범위를 사용자가 확인해 등록한다. 자유 서술 TXT를 임의로 표로 변환하지 않고, 컬럼의 업무 의미를 추측하거나 이름 변경을 강제하지 않는다.
- **분석 근거:** 결과 가까이에 부분/전체 분석 범위, 실제 분석 행 수 또는 제한 상한, 중요한 한계를 짧게 설명하고 선택 방식·Seed·판본·알고리즘은 펼쳐 확인한다. 정확도는 개별 지표에 적용하며, 제공되지 않은 처리 행 수·계산 방법은 확인 불가로 표현한다. 그룹 일부만 표시할 때 분석 대상 자체가 일부였던 것처럼 오해시키지 않는다.
- **명시적 실행:** 예제 등록, 프로파일, 전체 집계, 변환은 사용자가 선택할 때만 실행한다. 등록 성공·분석 실패·취소는 서로 다른 사건이며, 분석의 실패나 취소가 원본 등록의 성공을 취소하지 않는다.
- **상태 유지:** 수정했지만 실행하지 않은 조건과 마지막으로 적용한 결과를 구별한다. Dataset을 바꾸거나 새 요청이 앞선 요청을 대체하면 과거 결과가 새 Dataset의 내용처럼 보이지 않게 하되, 같은 Dataset의 재조회에서는 편집 중인 선택을 잃지 않는다. 선택한 Dataset은 직접 URL·새로고침·뒤로 가기에서도 유지한다.
- **작업 이력:** 제출한 작업을 바로 선택해 상태·결과를 보고, 목록 페이지 밖의 작업도 직접 조회한다. 조회 실패를 작업 실패나 빈 이력으로 표시하지 않고 마지막 확인 상태와 재조회 경로를 제공한다.

Data Explorer(이해·조회·탐색)와 Data Preparation(Feature·Transform·Iceberg 적재)은 각각 독립적으로 시작하며 Dataset 참조와 Job 이력을 공유한다.

## 저장소·접근·보존

저장소 상태 화면은 기본 보존값, 실제 적용값과 설정 출처, 마지막 성공 검사 시각, 현재 보이는 범위를 표시하고 재검사 실패 시 마지막 결과가 현재 상태가 아님을 명시한다. **보호 중·관측 대기·검토 후보·확인 필요**를 구분하며 검사는 삭제가 아니다. 삭제 승인·직전 재검증 기능이 없으므로 삭제 제어 UI를 제공하지 않는다.

읽을 수 있는 Snapshot과 Tag가 확인된 보존 Snapshot을 구분하고, 보호 미설정 Dataset을 보존된 것으로 표시하지 않는다. Snapshot 목록은 해당 Iceberg Dataset 소유자나 운영 진단 권한에만 보이며, 타 사용자의 테이블 이름을 추측해 Snapshot에 연결할 수 없다. 보안 감사 조회와 데이터 삭제는 별도 권한이다. 로그인·권한 없음·보존 실패·감사 조회 상태를 분명하게 전달한다. 개발 모드 신원은 로컬에서만 사용하며 운영 토큰은 브라우저 저장소에 기록하지 않는다.

## 상호작용의 원칙

- **상태와 제어:** 접수·대기·실행·완료·실패·취소 상태의 의미는 [Workflows](workflows.md)를 따른다. 취소 요청을 즉시 취소 완료로 표시하지 않는다.
- **실패와 복구:** 입력 오류, 권한 문제, Runtime 불일치, 작업 실행 실패를 구분하고 가능한 다음 행동을 제시한다. 오류 안내는 실제 원인과 다음 행동을 먼저 보여주고 오류 코드·요청 ID는 참조 정보로 남긴다. 실행 권한이 없는 사용자에게는 현재 할 수 있는 일을 안내한다. 원인 불명일 때 성공처럼 표현하지 않는다.
- **결과의 신뢰:** 평가 지표에는 비교 조건·데이터 기준·제약을 함께 제공한다. 성공한 실행뿐 아니라 실패 기록도 다시 확인할 수 있게 한다.
- **조작 가능성:** 핵심 흐름은 명료한 명칭, 접근 가능한 피드백과 예측 가능한 상호작용으로 제공한다. 화면 제목·버튼·요약은 간결한 명사형으로 표기하고, 내부 식별자 대신 사용자 용어를 먼저 보여준다. 과도한 인프라 설정을 첫 사용의 전제 조건으로 만들지 않는다.
- **반복 검증:** UX, API 계약, 실제 End-to-End 실행을 함께 검토한다. 코드가 동작한다는 사실만으로 사용자 경험이 완성됐다고 판단하지 않는다.
