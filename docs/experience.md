# 사용자 경험

사용자 경험은 화면을 만드는 마지막 단계가 아니라, 기능의 경계·상태·API 계약을 결정하는 설계 입력이다. 기능은 사용자 목표와 성공 기준을 먼저 이해하고 UX, 계약, 구현, 검증을 반복해서 맞춘다. [제품 정체성](vision/PLATFORM_IDENTITY.md)의 Fork·Compare·Reproduce·Understand·Explore·Apply는 연구 경험의 기준이다.

## 이용자별 경험

![모델 개발·운영과 모델 체험·사용의 두 경험](references/builder-consumer-experience.png)

Builder / Operator는 모델·실행·평가·배포를 관리하고, Consumer / Explorer는 모델의 목적·제약·입출력을 확인하고 체험한다. 이는 고정된 계정 유형이 아닌 **사용 목적과 권한에 따른 경험의 차이**이며 한 사람도 두 경험을 모두 사용할 수 있다. 두 경험은 동일한 모델 판본과 평가 근거를 참조하지만 허용된 조작과 노출 정보는 다르다.

| 이용자 | 핵심 경험 |
| --- | --- |
| **Human** | 데이터 탐색·모델 개발·평가·배포 운영 또는 모델 소개·Playground·API 체험을 목적과 권한에 맞게 활용한다. 기술적 세부 정보는 필요할 때 단계적으로 제공한다. |
| **External System** | 명확한 요청·응답, 비동기 작업 식별, 상태 조회, 구조화된 오류, 중복 요청 처리와 예측 가능한 호환성에 기반해 연동한다. |
| **AI Agent** | 사람이 쓰는 핵심 기능을 공통 API·도구 계약으로 발견하고 사용할 수 있어야 한다. 작업의 권한과 부작용, 상태, 결과를 기계적으로 판독할 수 있어야 한다. |

웹 UI는 공통 플랫폼 기능을 활용한다. 특정 화면만 사용할 수 있는 숨겨진 핵심 기능이나 UI에 종속된 실행 계약을 만들지 않는다. API-first가 웹 사용성의 대체물은 아니다.

## 연구·실행의 목표 경험

1. **탐색:** 이용 가능한 데이터, 입력 스키마, 품질·시간 범위 및 제약을 이해한다.
2. **준비:** 모델과 평가 방법을 선택하고 기본 설정으로 시작하되, 필요 시 고급 설정을 조정한다. 실행 전 입력과 설정의 오류를 확인한다.
3. **실행:** 작업을 제출하고 식별자를 얻어 실제 상태와 진행 단계를 확인한다. 측정 불가능한 진행률을 추측해 표시하지 않는다.
4. **이해:** 결과와 지표, 실패 이유, 사용된 데이터·설정·모델·Runtime의 관계를 확인한다.
5. **발전:** 이전 실험과 비교하고, 재현하거나 분기해 새로운 실험을 수행하며, 모델을 추론·외부 서비스에서 재사용한다.

이 과정은 연구·실행 경험의 한 예시이지, 모든 실험에 강제되는 단일 화면이나 순서가 아니다. 연구자는 탐색·평가·추론 등 필요한 단계만 독립적으로 수행할 수 있다.

## 상호작용의 원칙

- **상태와 제어:** 접수·대기·실행·완료·실패·취소 상태의 의미는 [Workflows](workflows.md)를 따른다. 취소 요청을 즉시 취소 완료로 표시하지 않는다.
- **실패와 복구:** 입력 오류, 권한 문제, Runtime 불일치, 작업 실행 실패를 구분하고 가능한 다음 행동을 제시한다. 원인 불명일 때 성공처럼 표현하지 않는다.
- **결과의 신뢰:** 평가 지표에는 비교 조건·데이터 기준·제약을 함께 제공한다. 성공한 실행뿐 아니라 실패 기록도 후속 연구에 활용할 수 있게 한다.
- **조작 가능성:** 핵심 흐름은 명료한 명칭, 접근 가능한 피드백과 예측 가능한 상호작용으로 제공한다. 과도한 인프라 설정을 첫 사용의 전제 조건으로 만들지 않는다.
- **반복 검증:** UX 프로토타입, API 계약, 실제 End-to-End 실행을 함께 검토한다. 코드가 동작한다는 사실만으로 사용자 경험이 완성됐다고 판단하지 않는다.

구체적인 UI 구성·디자인 시스템은 이 정본이 고정하지 않는다. 실제로 따라 할 수 있는 설치·실행 절차는 구현 이후 `getting-started.md`에서 제공한다.

## 처음 보는 Dataset의 이해

지원하는 데이터를 새로 등록하면 구조와 기본 메타데이터를 먼저 확인할 수 있어야 한다. 시스템은 데이터 사전 없이 컬럼별 통계·품질·역할 후보를 제시하지만, 이름 힌트 등 불확실한 판단을 확정된 업무 의미로 표현하지 않는다. 표본·전체 범위와 근사·정확한 계산 결과를 혼동하지 않으며 원시 민감값을 자동 인사이트로 노출하지 않는다.

이해 결과는 입력 Dataset 판본과 계산 방법을 추적 가능한 별도 결과로 보존한다. 분석의 실패나 취소가 원본 등록의 성공을 취소하지 않는다. 탐색 후보는 통계·자료형·역할 후보에 기반한 실행 가능한 탐색 조건으로, 사용자 목적에 대한 적합성 권고가 아니다. 후보마다 구성 근거와 프로파일 범위를 설명하며, 선택 시 탐색 화면에 조건을 전달하고 사용자 확인·수정을 거쳐 실행한다. 사용자가 선택하지 않은 변환·대규모 작업을 조용히 실행하지 않는다. 처음 보는 데이터도 첫 번째 분석을 시작할 수 있고, 데이터 이해만으로 작업을 끝낼 수 있다.

## Data Workspace의 첫 사용

현재 구현 UI는 **Data Explorer(데이터 탐색)**와 **Data Preparation(데이터 준비)**을 별도 작업 영역으로 제공한다. Explorer의 Dataset 탭은 **데이터 이해·데이터 조회·탐색**이며, 데이터의 구조와 특성을 파악하고 분석 근거를 검증하는 것 자체로 완료할 수 있다. 데이터 이해는 원본 개요·판본·프로파일·역할 후보·탐색 후보를 제공한다. 데이터 조회는 행 투영·필터·정렬, 탐색은 조건 편집·집계·차트를 제공한다. Preparation은 기존 Feature Recipe·Transform Job·Iceberg 적재를 담당하며 Explorer를 먼저 거칠 필요가 없다. Preparation에서 데이터 등록·연결을 수행하면 해당 Dataset을 선택한 채 Preparation 영역을 유지한다. 두 영역은 Dataset 참조와 실행 계약을 공유한다. 전역 Jobs·Storage·Audit는 권한에 따라 별도로 노출된다.

표시용 인스턴스명은 제품 브랜드 SOS, 인증 모드, 실제 배포 주소·권한·소유권과 별도다. 인증 모드는 신원 API의 mode를 정본으로 사용하며 이를 배포 환경으로 표기하지 않는다. 표시 설정 요청이 실패했을 때는 임의의 인스턴스명을 생성하지 않고 재조회할 수 있어야 한다. 같은 인스턴스의 사용자는 동일한 서버 설정을 보며 **관리자만 변경**할 수 있다. 변경은 감사되며 사용자 로컬 저장소에만 저장하지 않는다. 환경 라벨은 인증 모드에 기반하며 접근 경로가 비공개라는 보안 보증으로 표현하지 않는다.

불필요한 계산을 피하기 위해 Dataset 이해 화면에서 기본 Preview·기존 EDA Profile을 미리 읽지 않는다. 필요한 탭에서 조회하고 같은 Dataset·재조회 판본에서는 결과를 재사용한다. Overview는 Workspace 수준에서 한 번 조회하여 데이터 이해와 탐색이 공유하고, 각 화면의 사용자 입력과 실패·재시도 상태는 독립적으로 유지한다. Dataset 전환 중 과거 응답이 새 데이터 화면을 덮어쓰지 않으며, Preview·Profile 결과는 요청한 Dataset ID·재조회 세대와 일치할 때만 표시된다. 명시적 새로고침은 무효화를 수행한다.


데이터가 없는 첫 화면은 빈 상태만 보여주지 않고 **예제 탐색, 파일 가져오기, Iceberg 연결**을 선택할 수 있어야 한다. 예제는 합성 데이터로 출처와 버전을 명시하며, 사용자의 선택 이전에 Dataset을 자동 등록하거나 실행 결과를 꾸미지 않는다. 예제를 선택하면 일반 Dataset과 동일한 EDA·Feature·Job 흐름을 수행한다.

새 Dataset을 등록하면 원본 규모·판본·스키마로 탐색을 시작한다. 원본 메타데이터는 프로파일 실행 전후 항상 표시하고, 실제 분석 행 수·표본 방법·전체 계산 여부와 별도로 표현한다. 샘플 집계를 전체 통계처럼 표시하지 않고 정확한 전체 집계는 별도 Job에서 실행·취소·조회한다. 전체 집계가 완료되면 원시 JSON에 앞서 사용자에게 분석 조건·Dataset 판본·표 형태의 집계 결과와 그룹 제한 여부를 표시한다. NaN·Infinity는 실제 NULL과 표시상 구별하되 숫자 집계로 표현할 수 없는 결과는 무효 수치로 표시한다. DECIMAL·큰 정수의 정확한 문자열은 반올림해 차트에 표시하지 않고 표에서 그대로 제공하며, 실제 NULL 그룹과 전체 그룹을 구분한다. 컬럼명으로부터 시간·업무 의미를 확정하지 않는다.

Preview는 필요한 컬럼·필터·정렬·반환 행 수를 선택해 같은 Dataset 판본에서 조회할 수 있어야 한다. 넓은 스키마의 기본 결과 표는 처음 12개 컬럼만 표시하고 전체 표시를 선택할 수 있다. 사용자가 컬럼을 명시적으로 선택한 조회 결과는 선택한 컬럼을 모두 표시한다. 이는 서버 조회·데이터 권한 범위의 제한이 아니라 화면 표시 범위이며, 반환 행 수를 전체 조건 일치 건수로 표현하지 않는다. 단순 Feature 작업은 원본 전체 행수를 이유로 미리보기를 거부하지 않고, 전역 Window는 입력을 임의로 자르지 않는다. Iceberg 적재는 원본 계산량과 사용자 반환 행 수를 혼동하지 않으며 하나의 논리적 Snapshot으로 결과를 연결한다.

Preview와 EDA는 별도 요청·로딩·실패·재시도 상태를 갖는다. 데이터 이해의 기본 메타데이터는 프로파일 유무에 관계없이 조회 실패·재시도를 제공하고, Data Preparation은 원본 Preview를 읽지 못한 경우 원인을 표시하고 같은 Dataset에서 재시도한다. EDA 행 순서 차트는 사용자가 값과 가로축을 지정했을 때만 표시하며, 값 또는 가로축이 일정하면 의미 없는 변화 그래프를 만들지 않는다. 축 값으로 재정렬하지 않고 미리보기 행 순서대로 연결한다. 축 이름만으로 시간·단위를 확정하지 않는다. 같은 Dataset에서 데이터를 재요청해도 작성 중인 Feature 단계를 잃지 않으며, 변환 입력이 달라지면 이전 Preview를 표시하지 않는다. Feature 단계는 수정·재정렬이 가능하며 Lag 기간과 Rolling 윈도 크기를 조정할 수 있다. Jobs는 특정 Dataset의 하위 화면에 갇히지 않고 전체 작업의 상태·취소·결과 이동을 제공한다. 데이터별 결과에는 샘플링과 전체 계산 여부를 구분한다. 시계열 Feature 구성 시 시간 순서, 그룹 구분, Rolling 값에 현재 행이 포함된다는 점을 이해할 수 있어야 한다. 키보드 조작 등 접근성도 기능 검증 범위다.


같은 Dataset에서 미리보기·EDA를 다시 가져올 때는 사용자가 지정한 컬럼, 시각화 축, Data Preparation의 Feature 단계와 시간·그룹 기준을 유지한다. 데이터셋이 바뀌었을 때에만 선택 상태를 초기화한다. Jobs 목록은 최근 작업을 제한된 페이지로 표시하고 이전 작업을 명시적으로 더 불러온다. 개별 Job은 Attempt 전체를 탐색할 수 있게 유지한다.

## 저장소 보존·진단 경험

Storage Health는 기본 보존값, 실제 적용값과 설정 출처, 마지막 성공 검사 시각 및 현재 보이는 페이지 범위를 표시한다. 재검사에 실패하면 마지막 결과가 현재 상태가 아님을 명시한다. 소유권 확인과 데이터 보호를 우선하여 **보호 중·관측 대기·검토 후보·확인 필요**를 명확하게 구분하고, 오류에는 객체 삭제가 수행되지 않았음을 알린다. 검사와 삭제는 별도 작업이며, 현재 서비스는 검사만 제공한다. 삭제 승인·삭제 직전 재검증 기능이 없는 현재 단계에서는 삭제 제어 UI를 제공하지 않는다. 보안 감사 조회와 실제 데이터 삭제 권한은 별도 계약이다.

## 접근·보존 경험

읽을 수 있는 Snapshot과 실제 Tag가 확인된 보존 Snapshot을 구분한다. Snapshot 목록 조회는 해당 Iceberg Dataset 소유권 또는 운영 진단 권한으로 제한한다. 타 사용자의 테이블 이름을 추측해 Snapshot에 연결하는 것은 허용하지 않는다. 보호 미설정 Dataset을 무조건 보존된 것으로 표시하지 않는다. 로그인·권한 없음·보존 실패·감사 조회 상태를 사용자에게 분명하게 전달한다. 개발자 기본 신원은 로컬에서만 사용하며 운영 토큰은 브라우저 저장소에 기록하지 않는다.
