# Runtime

Runtime은 학습·평가·추론 등의 작업을 수행하는 **실제 실행 환경과 그 호환성**을 의미한다. 플랫폼 API·제어 로직과 실행 환경은 논리적으로 분리한다. 초기 구현에서 동일한 머신을 사용하더라도 이 경계를 유지한다.

## 환경의 두 표현

- **Runtime Specification:** 작업이 요구하는 Python·프레임워크·의존성, 실행 기능과 자원 조건을 표현한다. 특정 인프라 제공자나 컨테이너 제품을 전제로 하지 않는다.
- **Resolved Runtime:** 실제 실행에 사용된 환경을 식별할 수 있는 기록이다. 코드 리비전, 의존성 잠금 또는 환경 이미지의 식별 정보, 관련 시스템 라이브러리·플랫폼, GPU·드라이버 등 결과에 영향을 줄 수 있는 조건을 연결한다.

사용자에게는 가능한 기본 환경을 제안하되, 고급 사용자에게는 필요한 호환성 및 자원 요구를 지정할 수 있어야 한다. 지원하지 않는 조합은 실행 전에 가능한 한 검증하고 이유를 알려준다.

## 설계 원칙

1. **프레임워크와 코어의 분리:** TensorFlow/Keras를 우선 지원할 수 있지만 플랫폼의 공통 Job·Model·Artifact 계약은 프레임워크별 객체에 종속되지 않는다.
2. **작업 환경 격리:** 충돌할 수 있는 프레임워크·네이티브 의존성·실행 권한을 무조건 하나의 전역 Python 환경에 누적하지 않는다. 격리 방법은 작업 요구와 신뢰 수준에 맞게 선택한다.
3. **학습과 추론의 호환성:** 학습·모델 저장과 서빙용 복원은 서로 다른 환경일 수 있다. 모델 판본에는 필요한 전처리, 서명, 직렬화 형식과 호환 Runtime을 연결한다. 단순히 파일이 존재하는 것만으로 복원 가능하다고 보지 않는다.
4. **재현성의 범위:** 코드·설정·데이터·의존성·환경을 추적해 반복 실행을 가능하게 한다. 난수 고정만으로 하드웨어·병렬화·비결정적 연산의 완전한 동일성을 보장한다고 주장하지 않는다.
5. **점진적 변경:** Python·프레임워크·이미지 변경 시 기존 모델의 로드·전처리·학습·추론 호환성을 검증한다. 신규 환경을 제공해도 기존 모델의 실행 조건을 잃지 않도록 이력과 전환 방법을 관리한다.
6. **실행 안전:** 외부 모델·플러그인 및 사용자 코드는 자원 한도, 접근 권한, 비밀정보 경계를 고려해 실행한다.

Worker의 실행 시간·관측 RSS 예산은 `SOS_WORKER_MAX_SECONDS`(기본 1800초)·`SOS_WORKER_MAX_RSS_MIB`(기본 2048MiB)이다. 부모 프로세스는 자식의 초과를 감시해 종료하고 Job·Attempt에 전용 오류 코드를 남긴다. Linux `/proc` RSS 관측은 폴링 방식이며 cgroup·OS 수준의 엄격한 메모리 격리와 같지 않다. 외부 Iceberg 커밋은 시간·메모리 제한으로 중단되어도 성공/실패를 추측하지 않는다.

Iceberg의 비파티션 테이블 적재는 Polars 디스크 스테이징과 PyArrow RecordBatchReader를 이용해 입력 전체 Arrow Table을 만들지 않고 하나의 Snapshot으로 커밋한다. 임시 파일은 Attempt가 수행한 로컬 작업에만 속하며, 외부 커밋 실패 시 성공·미실행을 추측하지 않는다. 현재 PyIceberg가 Reader 기반 파티션 쓰기를 지원하지 않으므로, 기존 파티션 테이블만 종전 소규모 호환 경로를 유지한다. 데이터 파일·Snapshot·Tag는 범용 캐시 축출 대상이 아니다.

Dataset 원본 캐시는 `SOS_DATASET_CACHE_MIB`(기본 2048MiB) 한도로 관리한다. 파일별 PostgreSQL advisory lock을 읽기 Lease로 사용해 사용 중인 파일을 축출하지 않으며, 할당량 부족 시 최근 사용되지 않은 불변 해시 캐시 파일만 선택적으로 축출한다. 모든 후보가 사용 중이면 507 자원 오류로 거부한다. S3 원본과 게시 결과·Iceberg Snapshot은 이 정리의 대상이 아니다.

Discovery는 PostgreSQL advisory lock에 기반한 전역 실행 슬롯(`SOS_DISCOVERY_MAX_ACTIVE`, 기본 1개)을 사용하며 `SOS_DISCOVERY_WAIT_SECONDS`(기본 15초)를 초과하면 429 용량 오류를 반환한다. 잠금은 DuckDB 연결 종료와 함께 해제되며 여러 API 인스턴스에서도 공유된다. 향후 실행 슬롯을 늘리기 전 RSS와 합산 메모리·Spill 예산을 측정해야 한다.

Discovery는 요청·Worker 실행별 DuckDB 연결을 사용한다. DuckDB Python 인터페이스가 타임존 인식 타임스탬프를 반환할 때 필요한 `pytz`는 잠금된 실행 의존성으로 포함한다. 스레드·메모리·Spill 임시 디스크와 결과 그룹 수는 `DiscoveryPolicy` 설정으로 제한한다. 임의 SQL·원본 경로·자동 확장 로딩을 허용하지 않으며 파일별 접근을 제한한다. 큰 전체 분석은 기존 Worker 프로세스로 넘긴다. DuckDB 메모리 설정이 OS 수준의 물리 메모리 상한을 강제한다는 의미는 아니다.

현재 저장소의 Python **3.12**와 `uv.lock`은 **플랫폼 개발 환경의 기준**이다. 향후 모든 모델 Runtime의 버전이나 전체 OS·GPU 환경까지 고정한 것과 같지 않다. 프로젝트 버전 `0.0.1`도 개별 Runtime·모델·계약 버전의 대체물이 아니다.

가상환경, 컨테이너, 원격 Worker, GPU 관리 도구, 스케줄러는 위 요구를 만족시키는 구현 선택이다. 이 정본은 특정 제품, 배치 구조, 이미지 빌드 방법을 미리 강제하지 않는다. 관련 계약은 [Contracts](contracts.md), 실행 동작은 [Workflows](workflows.md)를 따른다.
